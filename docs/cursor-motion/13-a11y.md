## Vestibular disclosure (unchanged from 06, still owed in the final report)

Full wander (table speeds 75-105 px/s ±10%, legs 150-400 px,
persistent across the hero) is the most provocative decorative
motion short of flashing. Mitigation is the reduced-motion path
above, verified intact. NO speed cap is invented: no WCAG
criterion or evidence base gives a px/s threshold where 70 is
safe and 110 is not. Users WITHOUT the OS preference set still
see full wander; that is inherent to the opt-out model, true of
every site honoring the preference this way, and not a
ship-blocker. Touch wander has no hover explanation by nature;
it is decorative, smooth, and bounded, same as desktop.

## CORRECTION to a carried residual: cards do NOT bob under reduced motion

06 and the H-band comment (~1905) claim collage float still bobs
cards under reduced motion, grazing static chips just above band
edges (Seoul-awards to ~VH 703, CFC-gutaxis to ~VH 861). That does
NOT hold in the current code. Mechanism: the float animation name
comes from the stylesheet class only (1281:
`animation: mv-collage-float 12s ... infinite alternate`); the
per-item inline style sets ONLY `animationDuration` and
`animationDelay` (2392-2393), never `animation-name`. The general
reduced-motion rule (~2020: `.mv-collage-float { animation: none; }`)
has equal specificity to the base rule and later source order, so
it wins and sets animation-name to none; inline duration/delay
cannot resurrect a none name. The miniature kill rule (~2165)
carries `!important` as well. Reduced-motion users therefore see
fully static cards, not bobbing ones. The H-band comment wording
is stale; the bands themselves are unaffected (they hide chips
that would park, and static cards cannot graze a hidden chip
either way). No code change needed; the final report should carry
the corrected picture, not the stale one.
