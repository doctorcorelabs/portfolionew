# 06 - Accessibility: reduced-motion, vestibular safety, touch (wander round)

Base: HEAD `3ea8892`. Read-only; no source touched, no build, no push.
Verified from `src/sections/Hero.tsx` and
`docs/cursor-consistency/00-synthesis.md`.

## (a) Reduced-motion: static = the old anchors, per device

Wander changes trajectory, not rest geometry. Under
`prefers-reduced-motion: reduce` the loop never runs, so chips sit
where the loop would start them: the anchors. Adopt that, no new
static spots. Desktop wide: FAERS (0.90, 0.90), SS (0.505, 0.70),
CFC (0.30, 0.695), Seoul (0.80, 0.695). Desktop laptop: FAERS
(0.85, 0.04), SS (0.55, 0.70), Seoul (0.70, 0.695), CFC base (0.30,
0.695). Tablet: TABLET_ANCHORS per sub-band. Phone miniature:
MINI_CURSOR_CHIPS anchors (FAERS 0.26/0.30 pinned, SS 0.60/0.34,
Seoul anchorX 0.70).

Safe by construction: static at anchor is a subset of the verified
drift box, so it is clean wherever drift was verified clean.

H3/H4/H6: STAND, no re-verification, IF AND ONLY IF wander keeps
these anchors as rest positions. Trigger for a full re-scan: any
change to the rest position (stage-center rest, last-waypoint rest,
re-centered anchors). Then H3/H4/H6 bounds must be recomputed and
the full desktop rest-park scan redone.

What the reduced-motion user sees: 4 static chips at anchors (Seoul
hidden in H3/H4 bands, CFC hidden in H6 band), pills hidden
everywhere, no loop, no entrance fade, no parallax. Pills MUST stay
hidden: static-visible pills exposed the Seoul-pill vs review-old
park (P1) and the CFC-pill vs PosterWindow park, which is why pills
were re-hidden.

Residual disclosure (pre-existing, not from wander): collage card
float (CSS, +-8px vertical) still bobs under reduced-motion, so a
card can graze a static chip just above a band edge. The user sees
"chips static, cards still bobbing", not zero motion. Killing
collage float under reduced-motion is a separate one-line decision.
Also: the wander loop's reduced-motion early return must cover
mount, not just frames - interpolating from an off-stage start on
mount would flash motion before the first guard runs.

## (b) Vestibular safety: ship full wander, reduced-motion is the mitigation

Honest assessment: 70-110 px/s over 150-400 px legs, persistent
across the whole hero, is the most provocative class of decorative
motion short of flashing. A chip crosses the hero in ~2-5 s, in the
visual periphery, for as long as the hero is on screen, which can
cause vestibular discomfort or nausea (vection) and persistent
distraction. The chips are decorative, so risk/benefit is
asymmetric: all risk, zero information loss if reduced.

Recommendation: full-motion users keep the FULL wander, on the
onlines precedent (a public site ships this class of motion).
Mitigations, in strength order: (1) `prefers-reduced-motion` ->
static chips, pills hidden, loop off - primary mitigation, already
exists; preserve the early return in ALL THREE loops plus the CSS
`animation: none` block. (2) Smooth motion only: eased waypoints,
no jumps, no blinking, no opacity strobing; small chip labels
are less provocative than full-screen moving areas. (3) Wander on
chips ONLY, never collage cards or the word/frame.

Do NOT invent a speed cap. No WCAG criterion or evidence base gives
a px/s threshold where 70 is safe and 110 is not, so any cap would
be arbitrary. What WOULD justify a cap or reduction: user
complaints, user testing with vestibular-sensitive users, or a
future criterion with a threshold. Until then it is a product call,
not an accessibility finding.

WCAG, precisely scoped: 2.3.1 Three Flashes (A) does NOT apply to
wander or converge - zero flashes by construction; smooth
translation is not flashing.
2.3.3 Animation from Interactions (AAA) does NOT apply to wander
(autonomous on load, not interaction-triggered), but applies IF
converge is kept: hover starts a 0.22 s blend toward the word
rect. Covered today by the reduced-motion early return (loop off =
no converge). If wander drops converge, 2.3.3 stops applying to
chips - but that also removes hover-gather.

Residual risk to disclose: users who have NOT set the OS preference
but are sensitive still see full wander. That is inherent to the
`prefers-reduced-motion` model (opt-out, not default-static) and is
true of every site honoring the preference this way. It is not a
reason to default everyone to static.

## (c) Touch: wander runs on touch too, including phones

Today touch is drift-only because converge needs hover, and wander
needs no hover. The old gate does not apply. Recommendation:

| Device | Wander? | Reasoning |
|---|---|---|
| Touch tablet | Yes | Autonomous motion loses nothing on touch; consistency was the cursor round's whole point. Waypoint bounds must be fitted to tablet lanes (layout QA owns the numbers). |
| Touch phone (miniature) | Yes, in design px | A static miniature would be visibly inconsistent, and the miniature stage is otherwise frozen, so wander is its only life. Legs must be budgeted in miniature design coordinates (1160x600 stage), NOT desktop pixels: a 150-400 design-px leg renders as ~41-248 visual px at scale 0.276-0.620. Layout QA must re-derive the old miniature crossing budget (max 3 s continuous, max 12 px deep visual, written for 40 design-px drift) for wander legs. |
| Touch, converge | No change | No hover on touch, no tap-to-converge, no tap-to-start wander. Wander autostarts like desktop; a tap gate would make it invisible and inconsistent. |
| Touch, pills/parallax | No change | Pills stay hidden on touch; parallax stays off on touch; scroll modulation is a11y-neutral (keep or drop per the motion designer, but it must not fight waypoint interpolation). |
| Reduced-motion on touch | Static, same as desktop | The early return already covers both loops; preserve it on touch paths too. |

## (d) QA-a11y verification checklist

1. Reduced-motion static positions per device (desktop wide/laptop,
   tablet 3 sub-bands, miniature): chips at anchors, H3/H4/H6 hiding
   Seoul/CFC in their bands, no static chip parked on a card or
   glyph, pills hidden everywhere.
2. No loop running under reduced-motion: rAF not scheduled in any
   loop (verify early-return branches, and confirm no transform
   writes in DevTools under reduced-motion emulation, including on
   mount).
3. Entrance fade killed under reduced-motion; parallax off under
   reduced-motion and on touch.
4. Pills hidden under reduced-motion (all 3, all bands) - regression
   check against P1 (Seoul-pill vs review-old) and CFC-pill vs
   PosterWindow.
5. Touch behavior: wander runs on touch tablet and touch phone
   (miniature, design-px legs); no converge on touch; no tap gate;
   pills hidden on touch.
6. No auto-playing large-area flashing: chips move smoothly, no
   blinking, no opacity strobing at waypoint endpoints; zero
   flashes per second anywhere (WCAG 2.3.1, confirm by inspection).
7. If converge is kept: hover converge disabled under reduced-motion
   (loop off covers it); WCAG 2.3.3 noted as AAA-only. If converge
   is dropped: note 2.3.3 no longer applies to chips.
8. Static-spot trigger: if the implementation changes rest positions
   away from the anchors in (a), H3/H4/H6 + the full rest-park scan
   must be redone before ship; if anchors stay, H-bands stand.
9. Residual disclosures carried to the final report: card float
   still bobs under reduced-motion (chips static, cards not); full
   wander visible to users without the OS preference set; touch
   wander has no hover explanation.
